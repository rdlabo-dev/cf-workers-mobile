# Void React Pages + D1 sample

This is an independent application, not an npm workspace. It uses the official React/D1 starter generated by `createPagesStarterTemplate` from [voidzero-dev/void](https://github.com/voidzero-dev/void/blob/9ed64ba3a03776480fe7e82d3d334300345cc3c2/packages/void/src/cli/template.ts), pinned at commit `9ed64ba3a03776480fe7e82d3d334300345cc3c2`. The upstream MIT license is included. Void and @void/react are pinned to 1.1.12.

The starter page, loader, action, API route and schema retain their upstream behavior. `void.config.ts` uses defaults. `/client-only` adds one regression case: the same loader with `ssr = false`. It still needs D1 even though its initial HTML has no rendered page component. `/about` adds a public SSR page with a React state button for local rendering and hydration acceptance.

Use Node 24.21.0 or newer. From the repository root, after building the library and installing demo dependencies:

```sh
npm install --prefix demo/void
npm run build --prefix demo/void
npm run test:void --prefix demo
npm run test:void:routes --prefix demo
```

Tests live in `../tests/void/` and create an ephemeral local D1 database. They do not deploy or access a Cloudflare account. Chromium and WebKit must be installed through Playwright. CI runs this sample in its own parallel compatibility job.

See [Void integration and limits](../../docs/void.md) for connecting the generated Worker to Capacitor. The Capacitor build copies `dist/client` through Vite’s `publicDir`; client assets are local while pages, loaders and actions remain remote. iOS simulator and Android emulator tests reject remote requests for bundled assets and cover SSR, hydration, form actions, D1 persistence and client-only rendering using the published packages without router patches. This sample has no authentication; do not deploy it as a production data endpoint.

To run native acceptance, set `UPSTREAM_PLATFORM=ios|android` and `UPSTREAM_DEVICE` to a booted simulator/emulator, then run `node --test demo/tests/void/native.test.mjs` from the repository root. Run the two platforms serially because they share the test shell.

Set `VOID_ROUTES=1` on the native test command to verify public GET route execution. This profile starts at `/about`, checks its hydrated counter and the local `/api/hello`, then exercises authenticated remote selection and the existing D1 form flow. Both platforms assert that public page/API requests never reach the backend. Native evidence is written to `demo/artifacts/void-routes-native/`.
